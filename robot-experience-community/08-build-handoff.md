# 08. 구축 인계서 — 로봇 경험 공유 커뮤니티 웹 v1 (가칭 "로봇 습관")

작성: 2026-11-14 · 받는 곳: 라온로그 서버의 Claude (구축 담당) · 보내는 곳: 기획 (허경원)

> **이 문서를 가장 먼저 읽어 주세요.** 기획은 끝났고, 이제 만들 차례입니다.
> 이 문서는 "무엇부터, 어떤 규칙으로, 어디까지 만들면 끝인지"를 정합니다.
> 화면 하나하나의 세부는 06, 결정의 근거는 DECISIONS에 있습니다. 여기서는 그 문서들을 다시 쓰지 않고 **가리킵니다.**

## 1. 한 줄로

가정용 로봇(마이크로덕·Reachy Mini 등) 소유자가 로봇에게 가르칠 **"팩"을 찾고 → 공식 경로로 설치하고 → "해봤어요"로 결과를 나누는** 한국어 커뮤니티 웹을, **모바일 우선 반응형 웹**으로 만듭니다. 로봇 행동 파일은 허깅페이스(HF)에 있고, **우리는 파일을 보관하지 않습니다.**

## 4. v1 범위

### 4-1. 만드는 것

- **P0** (출시에 반드시): SCR-01 홈, 02 팩 찾기, 03 팩 상세(탭 5), 04 설치하기 흐름, 05 해봤어요 쓰기, 06 질문하기·문제 알리기, 08 커뮤니티, 09 방, 10 글쓰기, 11 글 상세, 15 검색, 16 내 공간, 18 내 로봇 등록, 19 보유 인증, 20 팩 올리기 마법사, 22 가입·로그인, 23 [+] 시트, 24 신고, 25 영상 올리기 확인, ADM-01 검토 대기열
- **P1** (v1에 단순하게): SCR-12 챌린지, 13 배우기, 14 모음, 17 공개 프로필, 21 알림, 26 설정, ADM-02 콘텐츠 관리

### 4-2. 만들지 않는 것 (v1)

DECISIONS 2부에서 "나중에·제외"인 것 전부. 특히 혼동하기 쉬운 것:
- 별점, 비추천, 카르마·순위, 잔디, 어워드, 광고 (제외)
- 원클릭 자동 설치, 웹 시뮬레이터 미리 보기(E5), 댓글 영상(C18), AI 요약(C17), HF 계정 연결 자동 등록(D8), 로봇 기록 자동 채우기(B12), 위험 버전 자동 경고(B7), 사용자 모음, 팔로우, 후원·유료 팩·교육 구독 (나중에)
- 앱(iOS/Android), 로고 (범위 밖)

### 4-3. 조건부로 만드는 것

- **시뮬 테스트(B1)**: 마이크로덕 행동 팩을 시뮬레이터에서 100회 돌려 넘어짐 수를 세는 기능. **실현 가능성이 아직 확인되지 않았습니다.** v1에서는 숫자 표시 자리와 데이터 칸(`sim_runs`, `sim_falls`, 상태 "준비 중")만 만들고, 자동 실행 파이프라인은 별도 확인 후 착수합니다. 화면은 시뮬 부분이 통째로 빠져도 깨지지 않게 만들어 주세요.

**숫자 계산** (R4, 버전별)
- `n` = 그 버전의 해봤어요 수 / 성공률 = success ÷ n / 넘어짐 = fell=true ÷ n ("일부 성공"은 성공률에 넣지 않고 따로 셈)
- 카드에는 최신 버전 숫자. 최신 버전 n < 5면 직전 버전 숫자를 함께 보여 줌 (A5)
- "인기" 정렬 = 최근 30일 해봤어요 수 / "성공률" 정렬 = n ≥ 5인 팩만 (C5)

## 6. 외부 연동 — 허깅페이스 (자세한 근거: evidence 3-1, 3-3)

- **쓰는 방법**: 제작자가 원본 주소를 붙여 넣으면 HF 공개 API로 저장소 정보를 읽고, 마이크로덕이면 `manifest.json`(설명 파일)을 읽어 **대상 기종·동작 종류(kind)·설치 자리(slot)·라이선스·최신 리비전**을 올리기 마법사에 미리 채웁니다 (S8 개정).
- **하지 않는 것**: 목록 전체를 주기적으로 긁어 오기, 파일 내려받아 보관하기, HF 로고 사용.
- **사용량 제한**: 5분당 무료 계정 1,000회 (2025-09 기준). 토큰을 붙여 호출하고, 결과는 저장해 두고 다시 쓰기.
- **HF 토큰**은 코드·저장소에 넣지 말고 서버 환경 설정(비밀 값)으로.
- **출시 전 확인 필요**: HF 현재 약관 원문 (막는 조항은 찾지 못했으나 원문 미확인).

## 7. 기술 선택 — 서버 Claude가 제안해 주세요

기술 스택은 **정하지 않았습니다.** 라온로그 서버의 현재 구성(언어·프레임워크·DB·웹 서버·배포 방식·백업)을 먼저 살펴보고, 그에 맞는 안을 제안해 주세요. 조건은 아래와 같습니다.

| 조건 | 내용 |
|---|---|
| 화면 | 모바일 우선 반응형 웹, 기준 360px / 데스크톱 1280px (07-6-4) |
| 언어 | 한국어 전용, 한국어 검색(팩·글 통합, C16) |
| 파일 | 사진·영상 업로드 (팩 소개 30초, 해봤어요 60초 이하) → 저장 공간·용량 계획 필요 |
| 로그인 | 간편 로그인 (카카오·네이버·구글 제안, **미확정**) → 처음엔 바꾸기 쉬운 구조로 |
| 운영 | 운영진 검토 대기열, 신고 24시간 처리 |
| 분리 | **기존 라온로그 서비스와 분리** (별도 디렉터리·포트·서브도메인 등). 블로그를 깨뜨리지 않을 것 |
| 디자인 | 디자인 시스템 결과물이 아직 없을 수 있음 → **06-7장 컴포넌트 이름(C-01~C-25)대로 만들고, 색·글꼴은 토큰으로 분리**해서 나중에 디자인을 끼워 넣기 쉽게 |

## 8. 진행 순서 (마일스톤)

| 단계 | 내용 | 끝나면 보여 줄 것 |
|---|---|---|
| **M0 계획** (코드 없음) | 문서 읽기 → 서버 현황 조사 → **질문 목록 + 구축 계획서**(스택, 폴더 구조, 데이터 모델 확정안, 배포 위치, 일정 추정) | 계획서 → **기획 승인 후 M1** |
| M1 기반 | 가입·로그인(임시 방식 가능), 기종·내 로봇 등록·보유 인증, 공통 틀(하단 탭·상단 메뉴), 검토 대기열 기본 | 휴대폰 화면에서 가입→로봇 등록→인증 신청 |
| M2 팩 | 팩 올리기 마법사(HF 자동 채움), 팩 찾기(필터·정렬), 팩 상세(소개·버전 탭), 설치하기 흐름, 설치 기록 | 마이크로덕 팩 1개를 올려서 찾고 설치 안내까지 |
| M3 신뢰·대화 | 해봤어요 + 숫자 규칙, 질문·문제(비슷한 글 추천·양식), 커뮤니티 방·글·댓글, 도움 됐어요, 신고, 글쓰기 전 안내, 새 계정 규칙 | 해봤어요 4건→5건일 때 숫자 모양이 바뀌는 것 |
| M4 마무리 | 홈 블록, 검색, 알림, 챌린지, 모음, 배우기, 설정, 콘텐츠 관리, 문구 점검 | 06-5장 핵심 흐름 3개를 처음부터 끝까지 |

각 단계가 끝나면 **짧은 보고**(만든 것 / 안 된 것 / 결정이 필요한 것)를 남겨 주세요.

## 9. 완료 기준 — 이게 되면 v1 완료

- [ ] 06-5장 **핵심 흐름 3개**(처음 온 소유자 / 안 돼서 묻는 소유자 / 제작자)가 휴대폰에서 끝까지 된다
- [ ] 해봤어요 4건인 팩은 % 없이 건수만, 5건이 되면 성공률·넘어짐 %가 보인다
- [ ] 시뮬 숫자와 실기 숫자가 따로 보이고, 시뮬 데이터가 없어도 화면이 깨지지 않는다
- [ ] 보유 인증이 없는 계정은 해봤어요를 못 쓰고 인증 안내가 뜬다
- [ ] 공개된 버전은 고칠 수 없고 새 버전만 낼 수 있다
- [ ] 허용 목록 밖 주소는 팩 원본으로 등록되지 않는다
- [ ] 가입 24시간 미만 계정의 링크 포함 글은 검토 후 공개된다
- [ ] 위험한 팩 신고가 들어오면 그 팩에 "확인 중" 띠가 뜨고 대기열 맨 위에 남은 시간과 함께 보인다
- [ ] 별점·비추천·공개 설치 수가 어디에도 없다
- [ ] 360px 화면에서 가로 스크롤이 없고, 누르는 곳이 44px 이상이며, 글자 대비가 WCAG 2.1 AA를 넘는다
- [ ] 화면 문구에 용어집의 "쓰지 않는 말"(리뷰·별점·포크·이슈·롤백·낙상 등)이 없다
- [ ] 기존 라온로그 블로그가 그대로 동작한다

## 10. 일하는 방식 (부탁)

1. **M0에서는 코드를 쓰지 말고 계획서와 질문부터** 주세요. 기획이 확인한 뒤 M1을 시작합니다.
2. **되돌리기 어려운 일은 먼저 물어 주세요**: 운영 DB 변경, 도메인·DNS, 외부 서비스 가입·결제, 기존 라온로그 설정 변경, 공개 배포.
3. **문서와 다르게 만들어야 하면** 먼저 이유와 함께 물어 주세요. 바뀐 결정은 DECISIONS.md에 "3부 · 구축 중 결정"으로 적어 두면, 기획 문서와 실제 서비스가 어긋나지 않습니다.
4. 비밀 값(HF 토큰, 로그인 키 등)은 저장소에 넣지 말아 주세요.
5. 사람이 확인해야 할 것(법률 문구, 로그인 종류, 상표)은 **자리 표시**로 두고 진행해 주세요.
