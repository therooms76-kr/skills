# 04. 로봇 경험 공유 커뮤니티 — 초기 뼈대 (초안 v0.1)

> 이 문서는 "집의 기둥과 방 배치도"입니다. 벽지·가구(세부 기능)는 05 검토 대장에서 하나씩 정합니다.
> 여기 적힌 모든 것은 **2단계 검토 전 초안**이며, 확정되면 DECISIONS.md로 옮깁니다.

## 1. 세 사이트를 어떻게 합치나 — 한 장 그림

```
              ┌─────────────────────────────────────────────────┐
  레딧에서 →   │  사람·대화 층   로봇별 라운지, 말머리, 자랑·질문, 챌린지     │
              ├─────────────────────────────────────────────────┤
  깃허브에서 → │  버전·협업 층   버전 기록, 되돌리기, 내 버전 만들기,        │
              │                문제 알리기, 자동 검증 ✅                 │
              ├─────────────────────────────────────────────────┤
  허깅페이스 → │  카탈로그·신뢰 층 경험팩 카드(정해진 칸), 필터, 모음,       │
              │                  미리 보기, 공식 제작 표시                │
              ╞═════════════════════════════════════════════════╡
              │  [우리가 새로 만드는 것]  한국어 · 멀티브랜드 · 실기 성공 숫자 │
              │                        · 우리 집 규칙/안전 설정 공유       │
              ╞═════════════════════════════════════════════════╡
  빌린다 →     │  뒷창고: 허깅페이스 허브, 유니트리 UniStore 등 (파일 보관·실행) │
              └─────────────────────────────────────────────────┘
```

쉽게 말하면: **허깅페이스의 진열장 + 깃허브의 버전 관리 + 레딧의 동네 게시판**을 한 페이지에 모으되,
진열품 자체(정책 파일)는 남의 창고에 두고 우리는 **안내판과 후기 게시판과 안전 검사소** 역할을 합니다.

## 2. 핵심 개념 (데이터의 기둥) — 7개

모든 화면은 아래 7개 개념의 조합입니다. 이 개념들이 정해져야 화면·DB·API를 그릴 수 있습니다.

| # | 개념 | 쉬운 말 | 어디서 왔나 | 주요 내용 |
|---|---|---|---|---|
| K1 | **로봇 기종** | 마이크로덕, Reachy Mini, 유니트리 Go2 … | (우리 고유) | 제조사, 지원 펌웨어 목록, 공식 설치 경로, 되돌리기 지원 여부 |
| K2 | **내 로봇** | 회원이 등록한 실제 로봇 한 대 | (우리 고유) | 기종, 펌웨어 버전, 별명, 우리 집 바닥 종류, 보유 인증 여부 |
| K3 | **경험팩** | 공유 단위. 사업계획서 3-2의 ①~⑤ | 허깅페이스 카드 + 깃허브 저장소 | 아래 3장의 카드 칸, 원작/변형 연결 |
| K4 | **버전** | 경험팩의 1.0, 1.1 … | 깃허브 릴리스 | 바뀐 점 한 줄, 뒷창고 연결 주소, 검증 결과 |
| K5 | **실기 보고** | "우리 집에서 해 봤어요" — 성공/실패 + 영상 + 환경 | (우리 고유, 핵심 차별점) | 내 로봇·버전·바닥·결과·영상. 이것이 쌓여 "성공 312회, 낙상률 2%"가 됨 |
| K6 | **글** | 라운지 게시글·질문·문제 알리기 | 레딧 게시글 + 깃허브 이슈 + HF 토론 | 말머리, 연결된 경험팩(선택), 해결됨 여부 |
| K7 | **사람 / 단체** | 회원, 학원·학교 계정 | 레딧 사용자 + 깃허브 조직 | 내 로봇들, 올린 팩, 기여 기록, 꼬리표(보유 인증·제작자·공식) |

보조 개념(1차에서는 단순하게): 댓글, 모음(컬렉션), 챌린지, 신고, 알림.

> 핵심 판단 포인트: **"후기"를 별점 대신 K5 실기 보고로 만든다**는 것이 이 뼈대의 가장 큰 결정입니다.
> 별점(★4.5)은 기분이고, 실기 보고는 결과입니다. 2단계에서 가장 먼저 확정할 항목입니다.

## 3. 경험팩 카드의 "정해진 칸" (초안)

허깅페이스 모델 카드 방식. 이 칸들이 그대로 필터·호환 표시·검색이 됩니다.

| 묶음 | 칸 | 예시 | 필수? |
|---|---|---|---|
| 기본 | 이름 / 한 줄 소개 | "문워크 — 뒤로 미끄러지듯 걷기" | 필수 |
| 기본 | 팩 종류 | 행동(①) / 우리 집 규칙(②) / 안전 설정(③) / 묶음 | 필수 |
| 호환 | 로봇 기종 · 펌웨어 범위 | 마이크로덕 v1.2 이상 | 필수 |
| 호환 | 필요한 다른 팩 | "기본 균형 팩 1.0 필요" | 선택 |
| 난이도 | 설치 난이도 / 사용 연령 | 초급 · 8세 이상 보호자 동반 | 필수 |
| 환경 | 잘 되는 바닥 / 안 되는 바닥 | 마루 ○ · 두꺼운 카펫 × | 필수 |
| 이야기(④) | 설명 · 설치 순서 · 30초 영상 | | 영상은 권장 |
| 한계와 위험 | 알려진 문제 · 주의할 점 | "배터리 20% 이하에서 넘어짐 늘어남" | 필수 |
| 신뢰(⑤) | 시뮬 검증 결과 · 실기 성공/실패 수 · 낙상률 | 자동 계산 | 자동 |
| 출처 | 제작자 · 원작(변형일 때) · 라이선스 · 뒷창고 주소 | Apache-2.0, HF 저장소 링크 | 필수 |

## 4. 사이트 지도 — 위쪽 메뉴 6개 + 올리기 버튼

```
[로고]  홈 | 경험팩 찾기 | 라운지 | 챌린지 | 배우기 | 내 공간        [+ 올리기]
```

| 메뉴 | 들어 있는 것 | 주로 닮은 곳 |
|---|---|---|
| **홈** | 내 로봇 기준 맞춤 화면: 이번 주 인기 팩, 내 로봇 라운지 새 글, 내 팩에 달린 보고, 진행 중 챌린지 | 레딧 홈 피드 |
| **경험팩 찾기** | 카탈로그. 왼쪽 필터(기종·펌웨어·팩 종류·난이도·바닥·검증), 정렬(인기·최신·성공률), 모음 | 허깅페이스 Models |
| **라운지** | 로봇별 라운지 + 주제 라운지(처음 왔어요 · 우리 집 규칙 · 교육 · 자유). 말머리: 질문/자랑/후기/정보/해결됨 | 레딧 서브레딧 |
| **챌린지** | 이번 주 과제("뒤로 걷기"), 참가 영상, 지난 챌린지 | 레딧 정기 글 + 행사 |
| **배우기** | 처음 산 날 가이드, 기종별 위키/FAQ, 교육 커리큘럼(학원용, 2단계) | 레딧 위키 + HF 문서 |
| **내 공간** | 내 로봇들, 설치한 팩·되돌리기 지점, 올린 팩, 내 보고·글, 찜, 알림 | 깃허브 프로필 |
| **+ 올리기** | 경험팩 올리기 마법사 / 글쓰기 / 실기 보고하기 | 깃허브 New repo + 레딧 글쓰기 |

## 5. 경험팩 상세 페이지 — 탭 구조

깃허브 저장소 페이지 + 허깅페이스 모델 페이지를 합친 모양입니다.

```
┌──────────────────────────────────────────────────────────┐
│ 문워크  v1.3   [마이크로덕 v1.2+] [초급] [시뮬 검증 ✅]          │
│ 실기 성공 312회 · 낙상률 2% · 설치 1,204 · 찜 88               │
│ 만든 사람: @뒤뚱아빠   원작: (없음)   변형 4개                    │
│                                       [미리 보기] [설치하기]   │
├──────────────────────────────────────────────────────────┤
│ 소개 | 실기 보고(48) | 질문·문제(5) | 버전 기록 | 변형(4)          │
├──────────────────────────────────────────────────────────┤
│ (소개 탭) 한국어 설명 · 30초 영상 · 설치 순서 · 잘 되는 바닥        │
│          · 한계와 위험 · 라이선스                                  │
└──────────────────────────────────────────────────────────┘
```

| 탭 | 내용 | 닮은 곳 |
|---|---|---|
| 소개 | 카드 칸 전부, 영상, 설치 순서 | HF 모델 카드 / 깃허브 README |
| 실기 보고 | 성공/실패 + 영상 + 환경(바닥·펌웨어). 실패 보고도 숨기지 않음 | (우리 고유) |
| 질문·문제 | 질문과 문제 알리기를 한 탭에, 말머리로 구분. 양식 제공, [해결됨] 표시 | HF 토론 탭 + 깃허브 이슈 |
| 버전 기록 | 버전마다 바뀐 점 + 그 버전의 성공률 → "1.2에서 나빠졌네" 비교 | 깃허브 릴리스 |
| 변형 | 이 팩을 바꿔 만든 팩들 ("카펫용 느린 문워크") | 깃허브 포크 + HF 계보 |

## 6. 첫 사용 흐름 — 세 부류 사용자

### 6-1. 일반 소유자 (80%) — "5분 안에 첫 성공"

```
가입 → 내 로봇 등록(기종·펌웨어·바닥) → 홈: "처음 산 날 해 볼 팩 5개" 모음
 → 팩 카드 → [미리 보기] → [설치하기] (설치 전 상태 저장 안내)
 → 로봇 회사 공식 경로로 설치 → 돌아와서 "됐어요/안 됐어요" 실기 보고(영상 선택)
 → 안 됐으면: 질문·문제 탭 양식으로 연결 / 됐으면: 라운지에 자랑 글 제안
```

### 6-2. 제작자 (5%) — "내가 만든 걸 남이 써 주는 기쁨"

```
뒷창고(HF 등)에 정책 파일 올림 → 우리 쪽 [+ 올리기] → 뒷창고 주소 붙여넣기
 → 카드 칸 채우기(마법사) → 시뮬 자동 검증 대기 → 공개
 → 실기 보고·질문 알림 받기 → 새 버전 올리기
```

### 6-3. 교육 기관 (15%) — "수업에 바로 쓰는 순서 있는 묶음" (2단계)

```
학원 계정 개설 → 커리큘럼 팩(12주) 구독 → 학생 계정 묶기
 → 주차별 과제 = 팩 + 챌린지 → 학생 결과물이 실기 보고로 쌓임
```

## 7. 역할과 권한 (초안)

| 역할 | 할 수 있는 것 | 되는 방법 |
|---|---|---|
| 방문자 | 보기만 | — |
| 회원 | 글·댓글, 찜, 질문 | 가입 |
| **보유 인증 회원** | + 실기 보고, 팩 설치 기록 | 로봇 사진/구매 인증 (사업계획서 Phase 0 이벤트와 연결) |
| 제작자 | + 경험팩 올리기 | 보유 인증 + 첫 팩 운영진 검토 |
| 라운지 관리자 | 자기 라운지 글 고정·숨기기 | 운영진이 지정 (레딧 모더레이터) |
| 공식 계정 | 공식 제작 표시 | 로봇 회사·학원 확인 |
| 운영진 | 전부 | — |

> "실기 보고는 보유 인증 회원만"이 신뢰 숫자를 지키는 핵심 장치입니다. 2단계 확정 대상.

## 8. 사업 단계와 뼈대의 관계

| 사업 단계 (사업계획서) | 뼈대 중 무엇을 쓰나 | 어디서 |
|---|---|---|
| Phase 0~1 (~2027.3) 카페 | 라운지(=카페 게시판), 말머리, 보유 인증, 경험팩 카드 양식(=정해진 글 양식), 실기 보고 양식, 주간 챌린지 | 네이버 카페 / 디스코드 |
| Phase 2 (2027.4~9) 웹 v1 | 경험팩 찾기·상세(탭 5개), 필터, 시뮬 검증 배지, 되돌리기 안내, 내 공간 | 자체 웹 |
| Phase 3 (2027.10~) | 교육 계정·커리큘럼, 제작자 후원·유료 팩, 원클릭 설치 | 자체 웹 |

> 즉 **카드 칸과 실기 보고 양식은 카페 단계에서 "글 양식"으로 먼저 시험**할 수 있습니다.
> 카페에서 사람들이 그 양식을 실제로 채우는지가, 웹에서 그 칸을 만들지의 근거가 됩니다.

## 9. 2단계에서 정할 질문 (열린 질문)

1. **후기 = 별점? 실기 보고?** — 이 뼈대는 실기 보고 중심. 별점을 아예 없앨지, 함께 둘지.
2. **비추천(▼)을 둘 것인가?** — 레딧식 비추천은 초보를 쫓아낼 위험 (01 참고).
3. **질문과 문제 알리기를 한 탭으로 합칠까, 나눌까?** — 깃허브는 나누고(이슈/토론), HF는 합침(토론 탭).
4. **라운지를 로봇별로 나눌까, 하나로 두고 말머리로 나눌까?** — 사용자가 수백 명일 때는 하나가 나을 수도.
5. **경험팩 ②③(우리 집 규칙·안전 설정)을 행동 팩과 같은 목록에 섞을까?** — 성격이 달라 별도 메뉴가 나을 수도.
6. **뒷창고 연결 방식** — HF 약관 확인 전까지 "링크만" vs "목록 자동 가져오기" 중 무엇으로 시작할지.
7. **이름** — 사업계획서 후보 "로봇 습관 / 길들이기 / 뒤뚱". 메뉴 이름(경험팩, 라운지 등)도 함께 정함.
