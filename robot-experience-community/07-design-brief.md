## 1. 한눈에 보는 의뢰

| 항목 | 내용 |
|---|---|
| 무엇 | 가정용 로봇 소유자들이 로봇에게 가르칠 "팩"을 찾고, 설치하고, 결과를 나누는 **커뮤니티 웹 서비스**의 디자인 |

## 2. 서비스를 30초로 설명하면

로봇은 이제 내장 칩에서 "몸에 익은 습관"으로 움직입니다. 그래서 로봇을 바꾸는 방법은 그 습관 파일을 갈아 끼우는 것입니다. 습관 파일은 허깅페이스 같은 개발자용 저장소에 이미 있지만, 영어로 되어 있고, 코드 저장소 모양이고, **"우리 집에서도 될까?"를 알려 주는 곳이 없습니다.**

로봇 습관은 그 위에 얹는 **일반인용 안내판**입니다.
- 한국어로 설명하고
- **"해봤어요"**(실제로 해 본 사람의 성공/실패 + 넘어짐 여부)를 모아 믿을 만한 숫자로 보여 주고
- 안전하게 설치하도록 안내하고
- 소유자들이 로봇 이야기를 나누는 방을 둡니다.

**별점은 없습니다.** 신뢰는 "몇 명이 해 봤고, 몇 번 성공했고, 몇 번 넘어졌나"에서 나옵니다. 이 서비스의 핵심이고, 디자인이 가장 공들여야 할 부분입니다.

## 3. 브랜드 방향

### 3-1. 키워드

| 담고 싶은 것 | 피하고 싶은 것 |
|---|---|
| 따뜻함 — 거실, 아이와 함께, 키우는 기쁨 | 차가운 기술 느낌 — 검정·네온, 회로 무늬, SF |
| 신뢰 — 정직한 숫자, 차분한 정보 | 과한 게임 느낌 — 점수, 순위, 반짝이는 보상 |
| 쉬움 — 처음 써도 길을 잃지 않음 | 개발자 도구 느낌 — 코드 글꼴, 빽빽한 표 |
| 기록 — 우리 로봇이 자라는 이야기 | 유아용 장난감 느낌 — 지나치게 둥글고 알록달록함 (어른이 주 사용자) |

### 3-2. 분위기 방향 제안 (디자인 시스템이 고르거나 섞어 주세요)

| 방향 | 한 줄 | 색·재질 느낌 | 어울리는 점 |
|---|---|---|---|
| A. 거실의 오후 | 햇볕 드는 거실에서 로봇과 노는 장면 | 따뜻한 미색 바탕, 나무·패브릭 톤, 부드러운 주황 포인트 | 부모·아이 사용자, "키우는" 느낌 |
| B. 관찰 노트 | 로봇이 자라는 걸 기록하는 공책 | 종이 질감 흰 바탕, 연필 회색, 차분한 초록·파랑 포인트 | 해봤어요 = 기록이라는 성격, 신뢰 |
| C. A + B | 바탕은 A의 따뜻함, 숫자·배지는 B의 차분함 | — | **작성자 추천**: 감정은 따뜻하게, 정보는 믿음직하게 |

### 3-3. 이름과 로고

- 서비스 이름은 가칭 **"로봇 습관"**입니다. 상표 검색 전이라 **로고는 만들지 않습니다.** 시안의 로고 자리에는 글자로만 "로봇 습관"이라고 넣어 주세요.
- 마스코트·캐릭터도 이번 범위에서는 빼 주세요 (나중에 이름이 정해지면 따로 의뢰).

### 3-4. 말투

따뜻하고 쉬운 존댓말("~해요"). 짧게, 다음 행동을 알려 주는 문장. 예시는 9장에 있습니다.

## 4. 디자인 원칙 (모든 화면에 같은 잣대)

1. **결과가 먼저 보인다.** 팩을 보면 이름 다음에 바로 "해봤어요 숫자"가 눈에 들어와야 합니다. 설명보다 결과가 먼저입니다.
2. **숫자는 정직하게.** 표본이 적으면 %를 쓰지 않고 건수만 씁니다 (5장 C-02). 시뮬레이션 결과와 실제 집 결과는 **절대 한 숫자로 섞지 않고**, 눈으로 봐도 다른 것임을 알 수 있게 합니다.
3. **안전은 눈에 띄게, 겁주지는 않게.** "주의 상자"와 "경고 띠"는 분명히 보여야 하지만, 빨간 경고로 가득한 화면은 피합니다. 단계(정보 → 주의 → 경고)를 나눠 주세요.
4. **한 손으로.** 휴대폰을 한 손에 들고, 다른 손으로 로봇을 만지는 상황입니다. 설치하기·해봤어요·영상 올리기는 엄지가 닿는 아래쪽에 둡니다.
5. **사람과 로봇의 이야기.** 영상과 사진(로봇이 실제 집에서 움직이는 모습)이 화면의 주인공입니다. 꾸밈보다 콘텐츠가 돋보이게 해 주세요.

## 5. 핵심 컴포넌트 — 특히 공들여 주실 것

전체 25개 목록은 06 화면 명세 7장에 있습니다. 그중 이 서비스만의 것, 즉 다른 디자인 시스템에서 가져다 쓸 수 없는 것 6개를 자세히 적습니다.

### C-02 숫자 표시 ★ 가장 중요

| 모드 | 조건 | 보이는 내용 (예) |
|---|---|---|
| 없음 | 해봤어요 0건 | "아직 해본 사람이 없어요" |
| **건수 모드** | 해봤어요 1~4건 | `해봤어요 3 · 성공 2` (비율·막대 없음) |
| **비율 모드** | 해봤어요 5건 이상 | `성공률 96%` 크게 + `(46/48)` 작게 + `넘어짐 4%` |
| 시뮬 표시 (따로) | 행동 팩만 | `시뮬 테스트 100회 · 넘어짐 3` / `시뮬 테스트 준비 중` / (규칙·안전 팩은 자리 없음) |

- 실기 숫자와 시뮬 숫자는 **모양이 달라야** 합니다 (예: 실기는 진한 숫자, 시뮬은 작은 배지).
- 크기 2가지: 카드용(작게) / 팩 상세 머리용(크게).
- 넘어짐 비율이 높을 때 색을 바꿀지는 디자인 시스템이 판단해 주세요. 다만 색만으로 뜻을 전하지는 않습니다 (8장).

### C-01 팩 카드

- 보이는 순서: 썸네일(30초 영상의 첫 화면) → 이름 → 종류 배지 → 숫자 표시(작게) → 기종·난이도 → (있으면) 경고 띠
- 변형: 세로 목록형(팩 찾기) / 가로 스크롤형(홈·모음)
- 상태: 기본 / 확인 중 띠 / 위험 버전 띠(2단계) / 호환 안 됨(흐리게 + "내 로봇과 맞지 않아요")

### C-03 종류 배지

- 4종: **행동** · **우리 집 규칙** · **안전 설정** · **묶음**
- 색 + 아이콘 + 글자를 함께 씁니다 (색만으로 구분하지 않음)

### C-07 결과 표시 (해봤어요 카드 안)

- 결과 3종: 성공 · 일부 성공 · 실패 + 넘어짐 있음/없음
- 빨강·초록만으로 구분하지 말아 주세요 (색약 사용자). 아이콘 모양으로도 구분합니다.
- 실패도 숨기지 않는 서비스입니다. 실패를 "부끄러운 것"이 아니라 **"다른 사람을 돕는 정보"**로 보이게 해 주세요.

### C-15 주의 상자 / C-16 경고 띠

| 단계 | 쓰는 곳 | 강도 |
|---|---|---|
| 정보 | 설치 자리 안내 ("걷기 자리의 동작이 바뀌어요") | 약함 |
| 주의 | 팩의 한계와 위험 (주의 상자, 소개 탭 맨 위) | 중간 — 항상 보이지만 화면을 가리지 않음 |
| 확인 중 | 위험 신고를 운영진이 확인하는 중 (경고 띠) | 중간 이상 |
| 경고 | 위험 버전 (2단계) | 강함 |

### C-05 꼬리표

- 4종: **보유 인증 ✓** · **제작자** · **공식** · **방 관리자**. 닉네임 옆에 작게, 여러 개 붙을 수 있습니다.
- "보유 인증 ✓"가 신뢰의 기본 단위이므로 가장 알아보기 쉽게 해 주세요.

## 6. 받고 싶은 결과물

### 6-1. 기초 토큰 (Foundations)

| 항목 | 요청 |
|---|---|
| 색 | 바탕·글자·선·포인트, 의미 색(정보·주의·경고·성공), 종류 배지 4색. **라이트 모드 시안 + 다크 모드 토큰** (다크 화면 시안은 필요 없음) |

## 8. 접근성 요구 (필수)

- 글자와 바탕 대비 **WCAG 2.1 AA** 이상 (본문 4.5:1, 큰 글자 3:1)
- 누르는 곳 최소 **44 × 44px**
- **색만으로 뜻을 전하지 않기**: 종류 배지·결과 표시·경고는 아이콘·글자를 함께 씁니다
- 글자 크기를 200%까지 키워도 깨지지 않는 배치
- 영상에는 재생·정지 조작이 분명하고, 자동 재생은 소리 없이 하거나 자동 재생하지 않음

## 11. 디자인 시스템에 여쭙고 싶은 것

1. 3-2의 분위기 방향 중 어느 쪽이 좋을지, 또는 다른 제안이 있는지
2. 숫자 표시(C-02)의 건수 모드와 비율 모드를 사용자가 "다른 것"으로 알아보면서도 한 가족처럼 보이게 하는 방법
3. 종류 배지 4색을 의미 색(정보·주의·경고·성공)과 겹치지 않게 고르는 방법
4. 다크 모드를 v1부터 켤지 (토큰은 요청, 화면 적용 여부는 상의)
