# 03. 허깅페이스(Hugging Face) 구조 분석 — "카탈로그와 신뢰" 층

> 한 줄 요약: 허깅페이스는 **AI 모델·데이터의 거대한 진열장**이고, 진열품마다 "설명 카드"와 "바로 써 보는 체험관"이 붙어 있습니다.
> 우리에게서 허깅페이스는 두 가지 역할을 합니다. ① 벤치마킹 대상(진열 방식), ② **실제 파일이 놓이는 뒷창고**(사업계획서 4-1의 "빌린다" 층).

※ 기능 설명은 2026년 기준 일반적으로 알려진 구조이며, Reachy Mini 앱스토어 관련 내용은 사업계획서(2026-08-31 직접 확인)를 따릅니다. 세부 화면은 4단계에서 다시 확인합니다.

---

## 1. 허깅페이스는 어떻게 생겼나 — 3층 구조

```
허브 (Hub)
 ├─ 모델 (Models)      ← AI 모델 진열장. 로봇 "정책 파일"도 여기 올라감
 ├─ 데이터셋 (Datasets) ← 학습용 자료. 로봇 시연 데이터(LeRobot 형식) 5.8만 개+
 ├─ 스페이스 (Spaces)   ← "바로 써 보는 체험관" (웹에서 돌아가는 작은 앱)
 │                       Reachy Mini 앱스토어도 Spaces 위에 있음
 └─ 사람 / 조직
     └─ 진열품마다: 카드(설명서) · 파일 · 토론 탭 · 좋아요 · 다운로드 수 · 태그
```

쉽게 말하면, **깃허브의 "상자" 구조 위에 "가게 진열대"를 얹은 곳**입니다.
깃허브는 만드는 사람 중심, 허깅페이스는 **고르고 가져다 쓰는 사람 중심**에 조금 더 가깝습니다.

## 2. 핵심 기능과 "왜 있는가"

| # | 기능 | 무엇인가 (쉬운 말) | 허깅페이스에 왜 필요한가 |
|---|---|---|---|
| H1 | 모델 카드 | 진열품의 설명 카드: 무엇을 하나, 어떻게 쓰나, 한계·위험, 학습 방법, 라이선스 | 써도 되는지, 어디까지 믿을지 판단하게 |
| H2 | 카드 머리말 (메타데이터) | 카드 위쪽의 정해진 칸들: 작업 종류, 언어, 라이선스, 기반 모델 | 이 칸들로 자동 필터·검색이 됨 |
| H3 | 태그 + 필터 사이드바 | 왼쪽에서 "작업 종류·라이브러리·언어·라이선스"로 걸러 보기 | 수백만 개 중에 내 것을 찾게 |
| H4 | 정렬 (트렌딩·좋아요·다운로드·최신) | "요즘 뜨는 것" 등 | 새로 온 사람이 뭘 볼지 모를 때 |
| H5 | 좋아요(♥) / 다운로드 수 | 인기 신호 두 개 | 많이 쓰이는 것 = 어느 정도 믿을 만한 것 |
| H6 | 스페이스 (체험관) | 설치 없이 웹에서 바로 실행해 보는 데모 | "써 보고 고르게" — 설명보다 체험이 빠름 |
| H7 | 위젯 (카드 안 바로 실행) | 카드 페이지 안에서 바로 입력해 보기 | 체험을 한 번 더 줄임 |
| H8 | 진열품별 토론 탭 | 모델마다 딸린 질문·제안 게시판 | 질문이 그 물건 옆에 쌓이게 |
| H9 | 컬렉션 | "입문자용 모음", "한국어 모델 모음"처럼 묶음 목록 | 큐레이션 — 누가 골라 준 목록 |
| H10 | 기반 모델 계보 | "이 모델은 저 모델을 고쳐 만든 것" 연결 | 원작 추적, 변형 모델 모아 보기 |
| H11 | 출입 제한 (Gated) | "약관 동의하면 받을 수 있음" | 위험·라이선스가 있는 물건을 조건부 공개 |
| H12 | 조직 페이지 | 회사·연구실 공식 계정, 인증 표시 | "공식 제작"인지 알게 |
| H13 | 리더보드 | 같은 시험으로 모델 점수 비교 | 객관적인 비교 기준 |
| H14 | 논문 페이지 / 블로그 / 짧은 글(Posts) | 소식·해설 글 | 진열품 말고 "이야기"로 사람을 모으려고 |
| H15 | 원클릭 설치 (Reachy Mini 앱스토어) | 스페이스 앱을 로봇에 한 번에 설치 | 로봇 소유자가 코드 없이 쓰게 |
| H16 | 안전 검사 (파일 스캔) | 올린 파일에 악성 코드가 있는지 자동 검사 | 받은 파일이 위험하지 않게 |
| H17 | 버전 기록 | 깃허브와 같은 방식의 변경 기록 | 되돌리기·추적 |
| H18 | 유료 계정 / 클라우드 학습 (HF Jobs 등) | 돈 내고 더 큰 계산 자원 | 회사 수익 |

## 3. Reachy Mini 앱스토어 — 가장 가까운 선행 사례 (사업계획서 근거)

- 로봇 약 1만 대, 앱 200개+, 제작자 150명+, 대부분 로봇 코딩 초보 (HF CEO 블로그, 2026-05).
- 2026-08-31 직접 확인 결과, 앱 카드에 있는 것: **실행 상태·조회수·제작자·날짜**.
  없는 것: **후기·별점·설치 수·검증 배지·한국어 설명**.
- 즉 허깅페이스는 "진열장"은 훌륭하지만 **"이거 우리 집에서 잘 되나?"를 알려 주는 층이 비어 있습니다.** 이 빈칸이 우리 자리입니다.

## 4. 허깅페이스에서 배울 점과 조심할 점

**배울 점**
- **카드의 "정해진 칸"이 곧 필터가 됩니다.** 경험팩 카드에 "로봇 기종·펌웨어·난이도·바닥 종류·팩 종류(행동/규칙/안전)" 칸을 정해 두면, 필터·호환 표시·검색이 저절로 생깁니다. 뼈대 설계에서 가장 먼저 정해야 할 것입니다.
- **"한계와 위험" 칸**을 카드에 의무로 두는 문화. 우리 카드에도 "이런 바닥에서는 넘어짐", "아이 손 근처 주의" 같은 칸이 필요합니다.
- **체험(스페이스) 먼저, 설치는 나중.** 마이크로덕 웹 시뮬레이터가 공개돼 있으므로, "설치 전에 시뮬레이터로 미리 보기"가 가능할 수 있습니다 (Phase 0 확인 과제).
- **컬렉션(누가 골라 준 목록)** 은 사람이 적은 초기에 특히 강합니다. 운영진이 "처음 산 날 해 볼 팩 5개"를 묶어 주면 됩니다.
- **계보(기반 모델)** = 깃허브의 포크와 같은 생각입니다. 둘을 합쳐 "원작 → 변형" 연결을 만듭니다.

**조심할 점**
- **허깅페이스와 같은 것을 만들면 지는 싸움입니다.** 파일 보관·실행·학습은 허깅페이스 것을 쓰고(연결만), 우리는 그 위의 한국어·후기·검증·멀티브랜드만 합니다 (사업계획서 2-4 경고).
- **다운로드 수·좋아요는 "잘 된다"는 증거가 아닙니다.** 우리에게 필요한 숫자는 "실기 성공 몇 회, 낙상률 몇 %" 같은 **결과 숫자**입니다.
- **허깅페이스 약관상 외부 카탈로그가 연결·설치 호출을 해도 되는지 미확인** (사업계획서 부록 C). 뼈대의 뒷단 연결 방식은 이 확인 뒤에 확정합니다.

## 5. 우리 쪽으로 옮기면

| 허깅페이스 개념 | 우리 커뮤니티에서 | 메모 |
|---|---|---|
| 모델 카드 + 머리말 | **경험팩 카드** — 정해진 칸(기종·펌웨어·난이도·바닥·팩 종류·한계와 위험) | 뼈대의 핵심 (04 참고) |
| 태그·필터 | **"내 로봇에 맞는 것만" 기본 필터** | 사업계획서 3-4 시나리오 1번 |
| 스페이스 | **"미리 보기"** — 웹 시뮬레이터 영상/실행 | 가능 여부는 Phase 0 확인 |
| 토론 탭 | 경험팩 페이지의 **질문 탭** | 02의 "문제 알리기"와 탭을 나눌지 합칠지 검토 |
| 컬렉션 | **"모음"** — 운영진·사용자가 묶은 팩 목록 | 초기 콜드스타트 대응 |
| 기반 모델 계보 | **원작 → 변형 연결** | 02의 포크와 통합 |
| 조직 인증 | **공식 제작 표시** (로봇 회사·학원) | |
| 원클릭 설치 | **설치 버튼 → 로봇 회사 공식 설치 경로로 넘겨줌** | 우리는 직접 설치하지 않음 |
| 다운로드·좋아요 | **설치 수 + 실기 성공 수 + 낙상률** | 숫자의 종류를 바꿈 |
