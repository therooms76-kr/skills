## 1. 한눈에 보는 사업 그림

### 한 줄 정의

**미션**: 로봇을 "사서 끝나는 기계"가 아니라 "여럿이 함께 키우는 존재"로 만드는 것.

가정용 피지컬 AI 로봇(마이크로덕·Reachy Mini·유니트리 등) 소유자들이 자기 로봇에게 가르친 **경험(행동 정책)·지시(우리 집 규칙)·요구사항(설정·안전 한계)**을 "경험 팩" 단위로 소개·공유·다운로드·업데이트하는 **일반 소유자용 커뮤니티 플랫폼**. 개발자용 코드 저장소(허깅페이스 허브, 유니트리 UniStore)가 이미 있으므로, 이 사업은 그 **위에 얹는 "일반인 층"**(한국어 설명·후기·호환 표시·안전 검증·원클릭 설치)에 집중한다.

### 왜 이 사업인가 — 결론 3줄

1. **사장님 가설은 맞다.** 로봇의 "반사신경"은 내장 칩에서 돈다(마이크로덕: Rockchip 칩에서 50Hz 온보드 정책 루프, 구글 Gemini Robotics On-Device, 1X NEO 온보드 GPU, 피겨 Helix 온보드). 그러면 로봇을 바꾸는 방법은 "칩에 올릴 경험을 바꾸는 것"이 되고, 경험을 유통하는 곳이 필요해진다.
2. **사람들은 실제로 공유한다.** Reachy Mini는 보급 약 1만 대에 앱 200개+, 제작자 150명+ — 그중 대부분이 로봇 코딩을 처음 해본 사람이다(허깅페이스 CEO 공식 블로그, 2026.5). 마이크로덕도 "물리적 행동을 AI 모델처럼 공유되게 하겠다"고 선언했다.
3. **그런데 빈칸은 "일반 소유자 층"이다.** 지금 있는 공유처는 전부 코드 저장소 형태이고(GitHub식), 로봇 브랜드마다 따로 있으며, 영어다. 아이보·벡터 리뷰의 공통 불만 — "할 수 있는 게 적다, 금방 질린다, 가르치기 어렵다" — 을 푸는 곳은 없다. 이 빈칸을 **한국어·멀티브랜드·일반인 눈높이**로 채운다.

## 2. 시장과 사용자 — 왜 지금인가

### 2-1. 기술이 방향을 정했다 — "내장 칩 + 경험 업데이트"

| 사실 | 의미 | 출처·기준시점 |
|---|---|---|

| 부류 | 누구 | 원하는 것 | 이 플랫폼에서 하는 일 |
|---|---|---|---|

근거: 유니트리 휴머노이드 매출의 74%가 연구·교육(P3, 분석가 해석)이고, 마이크로덕 타깃도 "AI 개발자"(Axios). 즉 초기 시장은 개발자·교육이 크고 일반 소유자는 그 다음에 온다. **플랫폼은 일반 소유자용으로 설계하되, 초기 콘텐츠와 매출은 제작자·교육에서 나온다.**

세 가지가 비어 있다: ① **브랜드를 가로지르는 층**(HF는 HF만, 유니트리는 유니트리만), ② **일반 소유자 눈높이**(설명·후기·호환·검증·한국어), ③ **한국 시장**(정부가 2030년까지 피지컬 AI 2.8조+휴머노이드 2.3조 투입 발표, 로보티즈가 마이크로덕 액추에이터 공급, LG가 2027년 홈로봇 사업 시작 예고 — 그런데 소유자 커뮤니티 인프라는 없음).

**경고 — 플랫폼사가 직접 하면 끝이다.** 허깅페이스가 Reachy Mini 앱스토어에 후기·한국어·검증을 붙이면 ②는 사라진다. 이 사업이 살아남는 조건은 "HF와 경쟁"이 아니라 **"HF 위에서, HF가 안 하는 일(멀티브랜드·한국어·일반인·교육)을 하는 것"**이다. 실제로 HF는 "닫힌 스토어를 안 만든다"고 선언했으므로, 그 오픈 저장소를 우리 카탈로그의 뒷단으로 쓰는 것이 허용되는 구조다(라이선스 Apache-2.0).

### 2-5. 조사의 한계 (정직하게)

- **국내 소유자 수는 존재하지 않는 데이터다.** 마이크로덕·Reachy Mini의 국가별 판매량은 비공개. Phase 0에서 카페 가입자·구매 인증으로 직접 센다.
- 마이크로덕 주문액($2.6M)은 회사 발표이며 실제 배송·환불은 미확인. 유니트리 앱 수(237), OpenMind 개발자 수(1,000+)는 2차 보도만 존재.
- "일반 소유자가 경험을 내려받고 싶어 한다"는 근거는 리뷰의 불만(할 게 적다·질린다)과 Reachy Mini 앱 제작자 수뿐이다. **일반 소유자의 지불 의사는 미확인** — Phase 0 인터뷰 과제.
- 소비자 로봇펫 시장 규모(원화) 공식 통계 없음. 휴머노이드 전망(IDC·골드만삭스·모건스탠리)은 전부 민간 추정(P3).

## 3. 제품 콘셉트 — "경험 팩"과 커뮤니티

### 3-1. 설계를 지배하는 세 원칙

1. **로봇 회사와 싸우지 않는다.** 경험 파일(정책·앱)은 로봇 회사의 공식 저장소(HF Hub 등)에 두고, 우리는 **찾기·고르기·믿기·설치하기·자랑하기**를 맡는다. 뒷단은 남의 것, 앞단은 우리 것.
2. **일반인이 5분 안에 성공 경험을 얻어야 한다.** "설치했는데 로봇이 넘어졌다"가 첫 경험이면 끝이다. 그래서 검증 배지·호환 표시·되돌리기가 핵심 기능이다.
3. **경험은 파일이 아니라 이야기다.** 같은 "뒤뚱걸음" 정책도 "우리 아이가 이름 붙인 오리 걸음"이 되면 공유된다. 후기·영상·이름 붙이기가 콘텐츠의 절반이다.

### 3-2. 공유 단위 — "경험 팩"의 구조

```
┌─ 경험 팩 (Experience Pack) ─────────────────────────────┐
│  ① 행동 (Behavior)      로봇 회사 저장소의 정책 파일·앱     │
│                          (ONNX 정책, HF Space 앱, 모션 파일) │
│                          → 우리가 저장하지 않고 "연결"만 함    │
│  ② 지시 (Instruction)   우리 집 규칙 — "현관 앞은 가지 마",  │
│                          "저녁 9시엔 조용히", 반응 성격 설정   │
│                          → 텍스트/설정값, 우리가 저장           │
│  ③ 요구사항 (Constraint) 안전 한계 — 속도 상한, 낙상 시 정지,   │
│                          바닥 종류(마루/카펫), 배터리 하한      │
│                          → 설정값, 우리가 저장                 │
│  ④ 이야기 (Story)       한국어 설명, 설치 순서, 영상, 후기,    │
│                          "우리 집에서 이렇게 됐어요"           │
│  ⑤ 신뢰 (Trust)         호환 로봇·펌웨어 표시, 검증 배지        │
│                          (시뮬 통과 / 실기 N회 성공 / 낙상률), │
│                          되돌리기 지점                        │
└──────────────────────────────────────────────────────────┘
```

사장님이 말한 "경험·지시·요구사항"이 그대로 ①②③이다. 여기에 일반인을 위한 ④⑤를 붙인 것이 이 제품의 정체다. **①은 이미 HF·유니트리가 유통한다. ②③④⑤를 유통하는 곳이 없다.**

### 3-3. 기능 우선순위

| 우선순위 | 기능 | 이유 |
|---|---|---|
| MVP(필수) | 경험 팩 카탈로그(로봇별·난이도별), 한국어 설명·설치 순서, 호환 로봇/펌웨어 표시, 후기·별점·영상 | 이것만으로 "HF Hub의 한국어 안내판" 역할 — 씨앗 커뮤니티의 카페를 구조화한 것 |
| MVP(차별화) | **검증 배지**(시뮬레이터 자동 테스트 통과 / 실기 성공 인증), **되돌리기**(설치 전 상태 저장), "우리 집 설정" 공유(②③) | 일반 소유자의 "무서워서 못 깔겠다"를 푸는 기능 — 코드 저장소에는 없음 |
| 2단계 | 원클릭 설치(로봇 회사 공식 설치 경로 호출), 로봇 등록·펌웨어 자동 인식, 주간 챌린지("이번 주: 뒤로 걷기") | 커뮤니티 활성화 장치 |
| 2단계 | 교육 커리큘럼 팩(12주 과정, 과제·채점 기준), 학급 대시보드 | 초기 매출원 |
| 3단계 | 제작자 보상(후원·유료 팩), "경험 맞춤 튜닝" 서비스(우리 집 바닥·가구에 맞춰 시뮬 재학습 대행 — HF Jobs 등 클라우드 학습 활용) | 수익화 |
| 하지 않음 | 자체 로봇 OS·자체 로봇 제작, 정책 파일 자체 호스팅(초기), LLM 상시 연결 기능 | 플랫폼사와 정면 충돌 / 온디바이스 방향과 반대 |

> **[사본 메모 — 원문 아님]** 2026-10 결정으로 바뀐 점: "별점"은 두지 않고 "해봤어요(실기 보고)"로 대체 (DECISIONS S3).

### 3-4. 첫 화면 시나리오 (일반 소유자)

1. 마이크로덕 소유자가 앱을 열면 "내 로봇: 마이크로덕 v1.2 펌웨어" 인식 → 호환 팩만 보인다.
2. "이번 주 인기: 문워크(초급, 검증 ✅ 실기 312회 성공, 낙상률 2%)" 카드 → 한국어 설명 + 30초 영상 + 후기 48개.
3. [설치] → "설치 전 상태를 저장했어요. 문제 있으면 [되돌리기]" → 로봇 회사 공식 설치 경로로 전달.
4. 성공하면 "우리 로봇 영상 올리기" → 후기가 쌓이고 검증 카운트가 올라간다.
5. "우리 집 규칙" 탭에서 "현관 금지, 밤 9시 조용히" 설정을 팩으로 저장 → 다른 마이크로덕 가정과 공유.

## 4. 기술 아키텍처 — 우리가 만드는 것과 빌리는 것

### 4-1. 3층 구조

```
┌──────────────── 우리가 만든다 ────────────────┐
│  앞단: 웹/앱 (카탈로그·후기·검증배지·되돌리기·설정 공유)   │
│  중간: 커넥터 (HF Hub API ↔ UniStore ↔ 기타 저장소를    │
│        하나의 "경험 팩" 목록으로 정규화, 호환성 DB)       │
└──────────────────┬───────────────────────────┘
                   │ 연결(호스팅 안 함)
┌──────────────── 빌린다 ─────────────────────┐
│  뒷단: 로봇 회사 저장소 (HF Hub 저장소·Spaces,           │
│        LeRobot 데이터셋 포맷, 유니트리 UniStore)         │
│  로봇: 온디바이스 실행 (RK3566 등 내장 칩, 50Hz 정책 루프) │
└──────────────────────────────────────────────┘
```

- **커넥터**가 기술의 핵심이다. LeRobot은 v0.4(2025-10)부터 서드파티 로봇을 플러그인(별도 파이썬 패키지)으로, v0.5(2026-03)부터 정책도 설치형 패키지로 다룬다. 즉 "정책 = 설치 가능한 패키지"라는 표준이 이미 있어서, 우리 카탈로그가 그 패키지 이름을 가리키기만 하면 된다.
- **검증 배지**는 두 층: (a) 시뮬레이터 자동 테스트 — 마이크로덕은 MuJoCo 시뮬과 HF Spaces 웹 시뮬레이터가 공개돼 있어 "이 정책을 시뮬에서 100회 돌려 낙상 N회"를 자동으로 잴 수 있다(우리 서버에서 실행). (b) 실기 인증 — 소유자가 영상을 올리면 카운트. 시뮬 자동 테스트는 **확인된 사실이 아닌 설계 가정**이며 Phase 0에서 실제로 돌려본다.
- **되돌리기**는 로봇 회사 SDK가 지원하는 범위에서만 가능하다(마이크로덕은 updaterd라는 업데이트 데몬이 있음 — GitHub 확인). 지원 안 되는 로봇은 "수동 되돌리기 안내"로 대체.
- 소프트웨어 회사 역량으로 전부 내재화 가능한 영역이다(웹·API·DB·간단한 시뮬 실행 파이프라인). 로봇 하드웨어는 만들지 않는다.

### 4-2. 왜 LLM 상시 연결이 아닌가 (사장님 가설의 기술적 근거)

| 이유 | 근거 |
|---|---|
| 반응 속도 | 마이크로덕 정책 루프 50Hz(초당 50번 판단). 클라우드 왕복(수백 ms)으로는 균형을 못 잡는다 |
| 연결 끊김 | 1X: "지하실·정원·와이파이 불안한 집"에서도 돌아야 한다. 머스크(2026-04 실적 콜, 전사 P3): "통신 끊겨도 옵티머스가 멈추면 안 된다" |
| 비용 | 로봇 1대당 LLM 상시 호출은 월 수만 원 — $399 로봇에 안 맞는다(추론) |
| 프라이버시 | 집 안 영상을 클라우드로 보내는 것에 대한 거부감(1X는 사람 블러 처리·출입금지 구역을 별도 조치) |

그래서 구조는 "**평소엔 내장 칩 + 가끔 큰 AI**"가 되고, 우리 플랫폼은 "내장 칩에 올릴 경험을 배포·업데이트하는 채널"이다. 앱 스토어가 앱을 폰에 내려주는 것과 같은 자리다.

## 5. 추진 단계 — 로봇이 도착하기 전에 할 일

### 5-1. Phase 0 — 검증 (2026.9~11, 로봇 없이)

| 과제 | 방법 | 통과 기준 |
|---|---|---|
| 국내 소유자 수 세기 | 네이버 카페/디스코드 "마이크로덕·Reachy Mini 한국 소유자 모임" 개설, 구매 인증 이벤트 | 3개월 내 구매 인증 **100명** |
| 공유 욕구 확인 | 카페에서 "내 로봇 첫 기술" 영상 공유 이벤트, 설문(어떤 팩이면 돈 내겠나) | 인증자의 30%가 콘텐츠 1건 이상 게시 |

| 교육 수요 | 코딩학원·방과후 업체 5곳 인터뷰 | 2곳 이상 "커리큘럼 팩 유료 구독 의향" |
| 플랫폼사 관계 | HF LeRobot 커뮤니티에 기여(한국어 문서·팩 3개 공개), Pollen에 "한국 커뮤니티 파트너" 제안 메일 | 회신 1건 |

### 5-2. Phase 1~2 — 씨앗 커뮤니티 → 플랫폼 v1

- **Phase 1 (2026.12~2027.3)**: 로봇이 도착하는 시점. 카페에서 운영진이 직접 만든 경험 팩 20개(문워크·인사·이름 부르면 오기·우리 집 규칙 템플릿 등)를 한국어 설명+영상으로 배포. 이 카페 활동 자체가 플랫폼 v1의 요구사항 명세가 된다.
- **Phase 2 (2027.4~9)**: 웹 플랫폼 v1. 카탈로그·호환표·후기·검증 배지·되돌리기. 카페 회원을 그대로 이관. 게이트: 월간 활성 사용자 500명, 팩 100개, 외부 제작자 비율 30%.

### 5-3. Phase 3~4 — 수익화와 B2B

- 제작자 보상(후원 버튼 → 유료 프리미엄 팩, 수수료 15%: HF의 "30% 안 받는다" 선언보다 낮게), 교육 커리큘럼 팩 구독(학원당 월 5~10만 원), "경험 맞춤 튜닝" 대행.
- 국내 제조사(로보티즈 — 마이크로덕 액추에이터 공급사이자 2026년 자체 휴머노이드 발표, LG — 2027년 홈로봇 사업 시작 예고)에 **커뮤니티/경험 유통 화이트라벨** 제안. 정부 피지컬 AI 사업(2030년까지 5.1조 투입 발표)의 "행동 데이터 학습 거점" 과제와 연계 검토.

### 5-4. 브랜드 방향

따뜻함(키우는 느낌) + 신뢰(검증). 네이밍 후보: **"로봇 습관"** (경험=습관 파일이라는 개념을 그대로), **"길들이기"**, **"뒤뚱"**(마이크로덕 첫 커뮤니티라면). 최종은 상표 검색 후 결정. 영어 병기 후보: HabitHub, TameLab.

## 부록 B. 예상 질문과 답 (요약)

1. **허깅페이스가 한국어·후기를 붙이면?** — 최대 리스크. HF는 자사 로봇만 다루므로 멀티브랜드 층은 남고, 처음부터 HF 커뮤니티 기여자로 들어가 "한국 파트너"로 붙는 게 출구.
2. **국내 소유자 수는?** — 존재하지 않는 데이터. Phase 0 카페 구매 인증으로 세고, 100명이 안 되면 플랫폼을 만들지 않음.
3. **일반인이 돈을 낼까?** — 미확인. 교육기관 구독과 제조사 B2B를 먼저.
4. **왜 지금?** — 55만 원 로봇(8/27), 정책 패키지 표준(LeRobot v0.5, 3월), 정부 피지컬 AI 5조(8/27)가 올해 겹침.
5. **온디바이스는 확실?** — 4개 회사 1차 자료로 확인. "그래서 유통 플랫폼이 필요하다"만 추론.
6. **로봇이 망가지면?** — 검증 배지·되돌리기·면책 고지. 마이크로덕은 "넘어지도록 설계"된 800g 로봇이라 첫 대상으로 안전. 휴머노이드 확장 시 별도 안전 정책.
